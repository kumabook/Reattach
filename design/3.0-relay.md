# 3.0: Reattach Relay（E2EE の中継トンネル）

## 目的

Tailscale も Cloudflare Tunnel も用意せずに、外から自分のマシンの tmux に届くようにする。中継はサブスク（Pro とは別）にし、直接つなぐ方式は今まで通り無料で残す。

打ち出し：「中継サーバーはあるが、中身は見えない。直接つなぐなら今まで通り無料」

## 方針：TLS をそのまま中継する

```
iPhone / Watch / Mac ──TLS──▶ [Relay: バイトを流すだけ] ◀── reattachd（外向きに常時接続、TLS を終端）
```

- Relay は TLS を解かない。接続 ID ごとに、アプリ側と reattachd 側のストリームをつなぐだけ。
- reattachd は自己署名の証明書を生成し、自分で TLS を終端する。
- ペアリングの QR に証明書の公開鍵の SPKI SHA-256 を入れ、アプリはその鍵だけを信用する（ピン留め）。QR は手元で読むため、鍵の受け渡しは Relay を通らない。
- REST、WebSocket、認証（デバイストークン）は変えない。変わるのは接続先と証明書の検証だけ。

自前の E2EE（Noise など）は採らない。HTTP と WebSocket を 1 本の暗号化された経路に束ね直す必要があり、4 つのクライアントすべてで作り直しになるため。

## 構成要素

### Relay（Cloudflare Workers と Durable Objects を想定）
- reattachd は `wss://relay.../agent/<machine-id>` に常時接続する。
- アプリは `wss://relay.../connect/<machine-id>` に接続し、Durable Object が両者を結ぶ。
  - 1 本の agent 接続に複数のクライアント接続が乗るので、多重化が必要。
  - 候補 1：agent 側にストリーム ID 付きのフレームで多重化する。
  - 候補 2：クライアントが来るたびに、reattachd に新しい agent 接続を張らせる。こちらの方がシンプル。
- 入口で認証する。
  - クライアント：App Store のサブスク（StoreKit 2 の署名付きトランザクション）を確認する。
  - agent：初回登録時に発行する machine トークン。
- 中身は見えない。見えるのは接続時刻と通信量だけ。ログにもそれ以上残さない。

### reattachd
- `reattachd init --relay`：machine を登録し、自己署名証明書を作り、Relay への常時接続を始める。
- Relay から来たストリームを、今の HTTP サーバー（axum）にそのまま流す。
- QR / setup URL に relay の接続先とフィンガープリントを入れる。

### アプリ（iPhone / Watch / Mac）
- サーバー設定に `pinnedKey` を持たせる。
- `URLSession` の delegate（`didReceive challenge`）で、ピン留めした鍵と照合する。WebSocket も同じ。
- サブスクの購入と、トランザクションを Relay に渡す処理。

## 残る責任・リスク

- **可用性**：Relay が落ちると、サブスクの利用者はつながらない。状態ページと、障害時の告知手段が必要。
- **メタデータ**：接続時刻と通信量は見える。キー入力のタイミングも、理屈の上では推測できる。プライバシーポリシーに明記する。
- **悪用**：汎用のトンネルにされないよう、サブスクの確認と、通信量・同時接続数の上限を設ける。
- **コスト**：Workers Paid は月 $5 から。Durable Objects は時間と転送量で課金される。ターミナルは文字だけなので小さいが、常時接続の時間課金は見積もる。
